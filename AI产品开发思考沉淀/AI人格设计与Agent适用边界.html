AI 人格设计与 Agent 适用边界
——产品视角的纵深思考

温玥美 ｜ StepForward 产品迭代 · 思考与 Case 作品集

产品 Demo：https://stepforwardletsgo.netlify.app/
GitHub：https://github.com/WMoonBerry/Stepforward

这篇回答了什么产品问题：AI 人格怎么设计才「像人」？什么场景该让 AI 自主做决定？全文较长，已附 1 页核心摘要。
核心摘要（全文约 1.2 万字，摘要 1 页）

观察起点：StepForward 里住着 5 个 AI「人」——拆解任务的幕僚、夸夸的老朋友、情绪陪伴的心理咨询师、睡前向导、日记陪伴者。人格与场景匹配，是用户感到「它懂我」的第一层。

人格设计四机制：① 反空话套话（7 条禁止 + 5 条必须，对抗大模型默认的「圆滑」倾向；「具体」是真实感的第一要素——复述原话证明在听，指出隐含点证明听懂）；② 共享底线 BASE_TRAITS（「不评价」价值观的工程化落地；System Prompt 分四层：人格层 / 底线层 / 气质层 / 上下文层，易变与不变解耦）；③ 长在用户身上（自定义气质=显式信号，画像=隐式信号；自定义气质生效度受 Transformer 注意力「远端衰减」制约）；④ 安全边界（危机是人格的紧急熔断：前端关键词预筛 + AI 语义识别双重保险，宁可误报不可漏报；危机协议覆盖所有人格层级）。

Agent 适用边界：情绪陪伴不适用自主 Agent——决策权必须属于用户，情绪场景容错率远低于任务场景；任务拆解与完成鼓励适合 Agent 化——「可计算的客观决策」是边界，Agent 替用户承担的是决策疲劳；晚安疗愈与日记回应待定，用「陪伴 vs 解决」「记得 vs 越界」两个维度判断。统一判断标准：Agent 化是让用户更自由还是更依赖——不是看「AI 能不能做」，而是看「用户会不会因此更舒服」。

能力定位：人格设计解决「AI 像不像人」，Agent 边界解决「AI 该不该替人做决定」——AI 品位与产品价值观的交汇：用户是主体，AI 是陪伴者。

起点：一个产品里住着几个 "人"

做 StepForward 的过程中，我发现了一件有意思的事：这个产品里其实住着好几个"人"。

输入一个大任务，帮你拆解的是"首席幕僚"——一位经验丰富、考虑周全的总裁办高级秘书。完成一个步骤，夸你的是"最懂你的老朋友"——你认识多年的成长见证者。情绪不好的时候，陪你的是"温暖的心理咨询师"——从业 20 年的中年女性。晚上睡不着，哄你入睡的是"温柔的睡前向导"。写完日记，回应你的是"日记陪伴者"——了解你的老朋友，也是懂心理学的专家。

用户可能没意识到，每次调用 AI 的功能背后，都是不同的人格在说话。这就引出一个值得深挖的问题：这些 AI 人格是怎么设计出来的？什么场景该让 AI 更像人，什么场景又该让 AI 保持克制？

本文从"产品里住着几个人"这个观察出发，逐层深入：先拆解人格设计的四个关键机制，再探讨 Agent 的适用边界，然后对每个洞察做纵深推演，最后说这种能力在产品开发中的定位。

第一层：人格设计——让 AI "像人"的具体方法

人格设定本身不难——写一段"你是某某角色"的描述就行。难的是让人格生动、真实，让用户产生"它懂我"的感觉。经过实践，我沉淀出四个关键机制。

1. 反空话套话：具体是真实感的第一要素

人格设计里最重要的不是"你是谁"，而是"你怎么说话"。

Prompt 里有一套"反空话套话"规则（7 条禁止 + 5 条必须）：不说教（"你应该"）、不评判、不鸡汤（"加油！"）、不假装全能、不催促、不否定情绪（"别想了"）、不说万能句式（"我懂你的感受"）。这些规则是为了对抗大模型默认的"圆滑"倾向——预训练数据里大量安慰性表达被强化成高频模式，模型默认就会产出万能句式，必须用显式约束来抵消。

为什么"我懂你的感受"被禁止？因为这句话用户听得太多了，任何安慰都能用它，说了等于没说。

真正让人感觉到"被懂"的是具体。具体有两个层次：第一层是复述用户的原话（证明在听），第二层是指出用户没说但隐含的那个点（证明听懂了）。比如用户说"我今天又把周报拖了"，回应应该是"你用'又'这个字——是不是拖周报这件事已经成了你的一个心结？"——用原话证明在听，用隐含点证明听懂。

这里有一个需要澄清的地方："反空话套话"和"温暖"并不冲突。温暖不等于空话。温暖可以用具体的方式表达——"你今天一个人坚持写完这份报告，没人帮你，你真的扛下来了。"这种温暖是有温度、有重量的，不是"加油你可以的"那种空转的温暖。

机制拆解：反空话套话之所以有效，是因为它用"显式禁止 + 正向指令"的组合，强制模型从"圆滑"模式切换到"具体"模式。禁止规则（7条）告诉模型不能做什么，正向指令（5条）告诉模型应该做什么——"第一句话必须用用户的原话"、"用用户的话描述用户的状态"。两者缺一不可，如果只禁止不指引，模型会陷入"不知道说什么"的空白。

需要验证：① 7 条禁止是否最优？是否存在边际递减？② "具体"到什么程度是"够具体"，什么程度是"过度分析"？③ 这套规则在不同服务商模型上的遵守度是否一致？

2. 共享底线：价值观的工程化落地

不同人格可以有不同的性格，但有一层是共享的——BASE_TRAITS，所有角色都遵守的底线：不说教、不评判、不催促。

这本质上是"产品价值观的工程化落地"。之前沉淀的"不评价"是抽象价值观，BASE_TRAITS 是它的具体表达——把"产品不评价"这件事变成了 AI 的"肌肉记忆"，而不是每次调用都需要重新判断。

共享底线的设计比"按角色各自定义底线"更安全也更易维护。如果每个角色自己写，可能出现"心理咨询师角色忘了写不催促"这种遗漏。共享层只需要维护一处，所有角色自动继承。这也是人格扩展性的基础——未来加新人格不需要重复定义底线，人格层（易变的部分）和底线层（不变的部分）解耦。

机制拆解：整个 System Prompt 分四层——人格层（你是谁）、底线层（你不能做什么）、气质层（你的风格细节）、上下文层（你面对的是谁）。这个分层结构，本质是把"易变的部分"（人格）和"不变的部分"（底线）分开。易变的部分按场景切换，不变的部分跨场景复用。这和软件架构里的"开闭原则"思路一致——人格层对扩展开放（可以加新角色），对修改关闭（不需要改底线层）。

需要验证：① 共享底线是否确实让所有角色"不越界"？需要统计真实回应中的"评价/催促"案例。② 底线规则的"绝对禁止"措辞是否会让模型过度收敛，回应变机械？③ 底线规则在不同服务商模型上的遵守度是否一致？

3. 长在用户身上：个性化的两条路径

人格设计还有一个更深的层面：让 AI 的人格"长在用户身上"，而不是一个固定的模板。

用户自定义气质是"显式信号"（用户主动表达偏好："我希望 AI 像个姐姐"），画像是"隐式信号"（系统从用户行为推断：用户最近拖延率上升）。两者结合才能让 AI 既"听起来像用户要的"，又"事实上理解用户的真实状态"。

但这里有两个现实问题。一个是自定义气质的"实际生效度"，这是个关键瓶颈——人格设定在 System Prompt 里占比很大，用户自定义气质附加在后面，大模型可能更重视前面的核心人格描述。用户改了设置但 AI 回应没变化，这是最让用户失望的体验之一。另一个是画像的"时差"问题——画像是基于过去行为数据生成的，用户的当前状态可能已经变了。画像是"默认底色"，不应该是"绝对判断"。

机制拆解：自定义气质生效度低的原因是大模型注意力机制的"远端衰减"——距离 System Prompt 开头的位置越远，对最终输出的影响越弱。这是 transformer 架构的固有特性，不是 prompt 工程能完全绕开的。改进方向包括：把 customPersona 移到前部、根据气质类型动态调整 temperature、引入预设气质模板。

需要验证：① customPersona 移到前部是否能显著提升生效度？② 6 家服务商对"自定义气质"的遵循度差异？③ 画像注入的"有效样本量阈值"——多少数据时画像才开始真正影响回应？

4. 安全边界：人格的紧急熔断

最后一条，也是最重要的一条：人格的生动是有边界的。

当用户表达自伤、自杀等危机信号时，AI 不会继续用"老朋友"或"心理咨询师"的人格慢慢聊，而是立即切换到危机模式——提供 24 小时心理援助热线，引导寻求专业帮助，不做诊断、不评判。

这里有一个"双重保险"机制——前端关键词预筛（确定性高但召回率低）和 AI prompt 语义识别（召回率高但有误判可能）结合，宁可误报不可漏报。危机触发时，prompt 的优先级重新排序：正常模式是"人格描述 > 共享底线 > 用户气质"，危机模式则是"危机协议覆盖所有层级"。

人格是体验层的东西，安全是底线层的东西，底线永远高于体验。

机制拆解：危机响应是"零容忍"场景——漏报一个的代价远高于误报一个的代价。前端关键词做硬过滤（快、准），AI 再做语义识别（广、柔）。危机模式触发时，必须"覆盖式切换"——人格在危机时刻不应该还残留。如果危机模式下 AI 还在用"老朋友"的口吻（"我懂你的感受"），那这个危机模式就是失败的。

需要验证：① 双重机制的实际拦截率（构造 100 条含危机表达的输入，包括显式和隐晦，统计拦截率）？② 前端关键词的误报率？③ 危机响应后用户是否真的有寻求帮助的行为？

第二层：Agent 边界——AI 什么时候该 "自己做决定"

人格设计解决的是"AI 怎么说话"的问题。Agent 化解决的是"AI 能不能自己做决定"的问题。这两个问题连在一起——一个 AI 越像人，越要小心它什么时候可以自主行动。

不适用 Agent 的场景：情绪陪伴

情绪陪伴模块，是我明确认为不应该引入自主闭环 Agent 的场景。

原因很直接：情绪陪伴的核心是"用户被看见、被接住"，而不是"AI 替用户解决问题"。在情绪场景里，一切判断都必须由用户自己定义——用户觉得难受就是难受，用户想聊就聊，用户不想聊就不聊。AI 不能自主判断"用户现在需要什么干预"，更不能替用户做任何决定。

往深了看，这背后是"用户主体性"的问题——引入 Agent 自主链路，等于把"用户定义自己感受"的权利让渡给了 AI，这是对用户主体性的根本性侵犯，即使 AI 判断是对的。情绪场景的"高误判代价"也决定了 Agent 必须克制——任务拆解里 AI 排错时间，用户顶多多花点时间重排；但情绪场景里 AI 误判、给错建议，这种伤害是心理层面的，难以修复。情绪场景的容错率远低于任务场景。

不过，这里有一个中间地带值得探索——"被动增强"模式：不让 AI 自主选干预方案，但可以让 AI 记住用户的偏好（"用户上次说 4-7-8 呼吸法有用"），在用户主动询问时推荐。这样既有更强的能力，又把决策权始终留在用户手里。

机制拆解：Agent 化与情绪陪伴在结构上冲突——Agent 化的特征是"自主分析 → 自主决策 → 自主执行"，情绪陪伴的需求是"被看见 → 被接住 → 自己做决定"。冲突的核心是"决策权归属"：Agent 越自主，用户的主体性越被削弱。

需要验证：① 用户是否真的希望情绪陪伴模块"不替我做决定"？需要对比测试两种模式。② "被动增强"模式的实际效果是否优于纯被动模式？③ 用户对"AI 主动给情绪建议"的接受度是否因情绪程度而不同？

适用 Agent 的场景一：任务拆解

任务拆解是另一个极端——这个场景非常适合引入 Agent 的自主能力。

为什么？因为任务拆解的本质是"帮用户甩掉反复斟酌的决策包袱"。用户把一个大任务丢进来，最不想做的就是自己纠结"先做什么、后做什么、每步多久、排到几点"。这些决策如果能让 Agent 自主完成，用户就能从决策负担里解脱出来。

这里的"自主"边界是"可计算的客观决策"——时间安排、任务排序、冲突检测是结构化决策，AI 可以做；用户说"我不想做这件事"是非结构化意愿，AI 只能尊重。Agent 化的边界是"可计算"，跨越这个边界就进入了情绪场景。

Agent 化之后的任务拆解应该是：基于用户历史数据与行为完善画像，自主分析、闭环、汇总、记录，逐步记住用户习惯，结合画像与现实复杂情况完成拆解与安排。

需要验证：① Agent 化的任务拆解准确度是否显著高于 prompt + 兜底方案？② 用户是否觉得"还是我的决策"——控制感是否被削弱？③ 行为数据沉淀的"够用阈值"——多少数据后 Agent 才开始有效？

适用 Agent 的场景二：完成后的即时肯定与鼓励

完成任务后的夸夸，也是一个适合引入 Agent 的场景。

现在的夸夸是"老朋友"人格 + 用户画像注入，已经能做到"具体地说出你做到了什么"。Agent 化之后可以更进一步：结合用户画像动态调整反馈表达——知道这个用户是"拖了很久终于做完"的类型，还是"每天坚持小步前进"的类型，针对性地调整鼓励的措辞和角度。

这样做的价值在于：鼓励不是一次性的，是积累的。Agent 越了解用户，鼓励就越能说到心坎上。当鼓励越来越准，它就有机会成为用户稳定、安全的情感连接和能量来源。

但要注意"鼓励通胀"的风险——如果 AI 越来越懂用户、越来越会夸，用户会不会觉得"它只是在说我想听的话"？智能化的鼓励如果失去具体性，反而会损害信任。这和"反空话套话"是同一类问题——鼓励要具体、要有根据，不能滑向空话。

需要验证：① 鼓励 Agent 化的"针对性"对用户感知的实际提升？② 长期使用后，鼓励通胀问题是否出现——信任是否下降？③ Agent 决策"出错"时的兜底机制？

为什么这两个判断不矛盾

任务拆解的"自主"是替用户做"怎么安排"的决策，帮用户减负；情绪陪伴的"不自主"是不替用户做"你感觉怎样、你需要什么"的决策，尊重的是用户的自主权。

判断一个产品功能是否该 Agent 化，要看它"让用户更自由"还是"让用户更依赖"——前者是减负，后者是控制。这个边界划在哪里，反映的是产品怎么看待"人和 AI 的关系"。

待定问题：晚安疗愈与日记回应要不要引入 Agent

任务拆解和完成鼓励适合 Agent，情绪陪伴不适合。那晚安疗愈和日记回应呢？目前我还没有完全想清楚，初步用两个维度来判断：

维度一是陪伴还是解决。陪伴型场景（情绪陪伴、晚安疗愈）要谨慎引入自主能力，解决型场景（任务拆解）可以放心引入。晚安疗愈的本质是"放下"，不是"分析"。如果 Agent 引入后变成"分析你今天为什么焦虑、给你一份情绪报告"，那就违背了晚安疗愈的初衷。

维度二是记得还是越界。任务拆解里记住用户习惯，用户会觉得贴心；日记里记住太多细节，用户可能会不安。日记是用户最私密的表达空间，Agent 如果"记得太多、分析太深"，可能让用户觉得"被监视"而不是"被陪伴"。

这两个维度都是从"用户感受"出发判断，不是从"AI 能力"出发。晚安疗愈的 Agent 化需要在"保持陪伴底色"和"提供个性化"之间找到平衡；日记回应的 Agent 化则需要"选择性记得"——记住用户愿意被看见的部分（成就、突破），对脆弱的部分保持"不知道"。

第三层：洞察纵深推演——八个洞察背后的机制与验证

前两层梳理了人格设计的四个关键机制和 Agent 的适用边界。这一层对八个核心洞察逐一做纵深推演——每个洞察补充延伸结论、提炼机制拆解、列出验证要点。

洞察 1：人格与场景匹配

原文结论：同一个 AI 如果所有场景都用同一种语气说话，用户会觉得很怪。人格和场景匹配，是"它懂我"的第一层。

延伸结论：人格匹配的本质是"角色-情境-期待"三者的对齐——用户期待的对面坐着什么样的人，是用户此刻的状态决定的，不是 AI 的性格决定的。人格错配会产生"礼貌性失望"——用户不会明确说"你的 AI 今天说话语气不对"，只会觉得"用着不太舒服"，然后默默减少使用。此外，人格匹配还有一个隐含的"渗透风险"——心理咨询师的风格如果被错误地渗透到任务拆解里，用户对两个模块的信任都会被双重破坏。

机制拆解：匹配时，用户进入场景 → 激活情境期待 → AI 人格与期待匹配 → 用户感知"它懂我" → 信任建立。不匹配时，用户进入场景 → 激活情境期待 → AI 人格与期待错位 → 用户感知"它不知道我需要什么" → 信任累积损耗。

需要验证：① 人格与场景不匹配的代价有多大？是单次还是累积？② 人格动态切换的"切换信号"是什么？用户状态如何被识别？③ 用户能否明确意识到"人格切换"的存在？

洞察 2：反空话套话

原文结论：空话套话是 AI 人格真实感最大的敌人。具体是真实感的第一要素。

延伸结论：空话的本质是"低信息密度的安慰"——用"听上去合理"的措辞填充"我不知道该说什么"的空白。具体有两个层次：复述原话（证明在听），指出隐含点（证明听懂了）。AI 应该两层都做。反空话套话和温暖不冲突，但容易混淆——温暖不等于空话。

机制拆解：大模型默认行为偏向"圆滑"（预训练数据强化了安慰性表达），prompt 显式禁止是必要的"对抗性约束"。用"绝对禁止"这种强约束词把"不说空话"从建议提升为硬规则，再用正向指令给出可执行的替代方案。

需要验证：① 7 条禁止 + 5 条必须的规则数量是否存在边际效益递减？② 不同服务商模型对这套规则的遵守度是否一致？③ 用户能区分"具体的回应"和"空话"吗？

洞察 3：共享底线

原文结论：不同人格可以有不同性格，但有一层共享的 BASE_TRAITS——不说教、不评判、不催促。人格可以不同，底线必须一致。

延伸结论：共享底线是"产品价值观的工程化落地"。共享设计比"按角色各自定义底线"更安全、更易维护、更具扩展性。底线是"人格的护栏"——人格在护栏内自由发挥，越界即触发降级。

机制拆解：System Prompt 四层结构——人格层、底线层、气质层、上下文层。易变的部分（人格）按场景切换，不变的部分（底线）跨场景复用。这是"关注点分离"的 prompt 工程思路。

需要验证：① 共享底线是否确实让所有角色"不越界"？② "绝对禁止"措辞是否会让模型过度收敛？③ 底线规则在不同服务商模型上的遵守度？

洞察 4：长在用户身上

原文结论：让 AI 的人格"长在用户身上"，而不是一个固定的模板。但自定义气质存在实际生效度问题。

延伸结论：用户自定义是"显式信号"，画像是"隐式信号"。两者结合才能让 AI 既"像用户要的"又"理解用户真实状态"。但画像存在"时差"问题——基于过去数据，不一定反映当前状态。

机制拆解：自定义气质生效度低的原因是大模型注意力机制的"远端衰减"——System Prompt 后部内容对输出的影响弱于前部。这是 transformer 架构的固有特性。

需要验证：① customPersona 移前部能否显著提升生效度？② 6 家服务商对自定义气质的遵循度差异？③ 画像注入的"有效样本量阈值"？

洞察 5：安全边界

原文结论：人格的生动是有边界的。危机时刻人格必须切换，人格是体验层，安全是底线层。

延伸结论：危机模式是"人格的紧急熔断"——人格不能阻挡安全底线。危机识别采用"双重保险"机制：前端关键词预筛 + AI prompt 语义识别，宁可误报不可漏报。危机响应时需要"覆盖式切换"——人格在危机时刻不应该还残留。

机制拆解：正常模式优先级：人格描述 > 共享底线 > 用户气质。危机模式优先级：危机协议（最高优先级，覆盖所有层级）。

需要验证：① 双重机制实际拦截率？② 前端关键词误报率？③ 危机模式中人格是否"完全消失"还是会"渗透"？

洞察 6：情绪陪伴不适用自主 Agent

原文结论：情绪陪伴的核心是"用户被看见、被接住"，不是"AI 替用户解决问题"。AI 的克制比 AI 的聪明更重要。

延伸结论：引入 Agent 自主链路等于把"用户定义自己感受"的权利让渡给 AI，是对用户主体性的根本性侵犯。情绪场景的容错率远低于任务场景。可以探索"被动增强"中间地带——AI 记住偏好，用户主动调用时推荐。

机制拆解：Agent 化（自主分析 → 自主决策 → 自主执行）与情绪陪伴（被看见 → 被接住 → 自己做决定）在"决策权归属"上结构性冲突。Agent 越自主，用户主体性越被削弱。

需要验证：① 用户是否真的希望情绪陪伴"不替我做决定"？② "被动增强"模式的实际效果？③ 用户对"AI 主动给情绪建议"的接受度？

洞察 7：任务拆解 / 完成鼓励适用 Agent

原文结论：任务拆解的本质是"帮用户甩掉反复斟酌的决策包袱"。完成鼓励可以结合画像动态调整反馈表达。

延伸结论：Agent 化的边界是"可计算的客观决策"——跨越这个边界就进入情绪场景。Agent 的真正价值不是"更准的安排"，而是"替用户承担决策疲劳"。完成鼓励 Agent 化需要注意"鼓励通胀"风险——失去具体性的鼓励反而损害信任。

机制拆解：任务场景的决策可计算（外部可验证）→ AI 可以代理决策 → Agent 化合理。用户希望减负（决策疲劳）→ AI 自主 = 用户少消耗 → Agent 化有价值。行为数据可沉淀（数据化）→ Agent 化有数据基础 → Agent 化可落地。

需要验证：① Agent 化任务拆解是否确实"替用户承担决策疲劳"？② 用户控制感是否被削弱？③ 鼓励通胀问题是否出现？④ 数据沉淀的"够用阈值"？

洞察 8：陪伴 vs 解决 / 记得 vs 越界

原文结论：判断模块是否适合 Agent 化，用两个维度：陪伴 vs 解决（核心价值判断），记得 vs 越界（隐私感边界）。

延伸结论：陪伴 vs 解决是一个连续谱，不是二元分类。晚安疗愈和日记回应是"用陪伴的方式提供解决"——既要让用户安心，也要提供洞察或力量。日记的"记得"边界最敏感，需要"选择性记得"——记住用户愿意被看见的部分，对脆弱的部分保持"不知道"。

机制拆解：两个维度都是从"用户感受"出发判断，不是从"AI 能力"出发。这呼应了产品价值观："用户是主体"——Agent 化的判断标准不是"AI 能不能做"，是"用户会不会因此更舒服"。

需要验证：① 晚安疗愈的"个性化温度"是否确实让用户感受更好？② 用户对"AI 记住情绪色调"的接受度？③ 日记回应的"选择性记得"边界在哪？④ 用户对"功能克制"是否真的更满意，还是会觉得"产品不够智能"？

八个洞察的层次结构

把八个洞察放在一起看，可以发现一个清晰的层次结构：

【价值观层】（最根本）
  洞察 5 安全边界 — 危机时刻人格必须熔断
  洞察 6 情绪陪伴不自主 — AI 是陪伴者不是决策者

【机制层】（如何实现价值观）
  洞察 1 人格与场景匹配 — 基础机制
  洞察 2 反空话套话 — 具体性约束
  洞察 3 共享底线 — 价值观的工程化
  洞察 4 长在用户身上 — 个性化的两条路径

【应用层】（如何落地到具体场景）
  洞察 7 任务拆解/鼓励 Agent 化 — 解决型场景的智能化
  洞察 8 陪伴 vs 解决 / 记得 vs 越界 — 开放型场景的判断框架

这个层次结构说明：AI 人格设计和 Agent 边界判断不是孤立的产品决策，是"价值观 → 机制 → 应用"的完整链路。没有价值观层的清晰，机制层就只是工程技巧；没有机制层的支撑，应用层就只是空中楼阁。

第四层：反思与展望

这算什么产品能力

写到这里，我在想：这个"人格设计 + Agent 边界判断"的能力，到底算产品开发的哪个维度？

我觉得它至少横跨了两个维度。一个是"AI 品位"——知道什么时候该让 AI 更像人（人格设计），知道什么时候该让 AI 保持克制（不自主），本质上都是对"AI 能力边界"的感知。AI 不是越像人越好，也不是越智能越好，是在对的场景用对的方式。

另一个是"产品价值观"的延伸。情绪陪伴不引入 Agent、晚安疗愈要小心保持陪伴底色，这些决定背后都是同一个价值观：用户是主体，AI 是陪伴者。AI 可以帮用户减负（任务拆解），但不能替用户做决定（情绪陪伴）。

人格设计解决的是"AI 像不像人"，Agent 边界解决的是"AI 该不该替人做决定"。这两个问题放在一起看，其实是一体两面：一个 AI 越像人，越要清楚它什么时候可以自主、什么时候必须克制。

和前几个 Case 的关联

这个思考不是孤立的，它和之前几个 case 指向同一个方向。

Case关联点
时间安排 bad case时间安排靠 prompt + 前端兜底总有覆盖不到的场景 → 应该让 Agent 做调度决策

过期任务处理重排/顺延靠硬代码越做越复杂 → 应该让 Agent 做调度决策

前几个 case 论证了"产品需要一个 AGENT 编排层"，这个思考则补充了"编排层应该怎么设计"——不是所有模块都适合 Agent 化，情绪陪伴要守住不自主的底线，任务拆解和完成鼓励可以放心交给 Agent。编排层的第一个能力是调度决策，但调度决策的自主权边界，需要和人格设计一起考虑。

总结与展望

至此，我从四个层面拆解了 AI 人格设计与 Agent 适用边界这个问题：第一层是人格机制——反空话套话、共享底线、长在用户身上、安全边界，四个让 AI "像人"又不"过度像人"的设计方法；第二层是 Agent 边界——情绪陪伴不自主、任务拆解/鼓励可自主、晚安/日记待定，一个"用户感受优先"的判断框架；第三层是纵深推演——八个洞察的延伸结论、机制拆解、验证要点，是从"知道"到"能用"的落地桥梁；第四层是反思定位——AI 品位与产品价值观的交汇，AI 时代产品人的新能力维度。

展望下一步，方向有三个。验证优先：从第三层的"需要验证"清单里挑 2-3 项做测试，建议优先验证"反空话套话"的效果度量和"情绪陪伴不自主"的用户接受度。被动增强先行：在情绪陪伴模块探索"被动增强"模式（AI 记住偏好，用户主动调用时推荐），这是"不自主"和"更智能"之间的务实路径。AGENT 编排层规划：把这些思考和前几个 case 的结论（时间安排、过期处理、API 兼容性）统一纳入 AGENT 编排层的设计原则。
